# Home surface

Mode: Operate. Users repeatedly open an app, read a notification, or find an app with one hand.

## Direction contract
THESIS: Niagara's vertical favorites and alphabetical navigation, explicitly chosen by the user.
OWN-WORLD: Transparent launcher over the system wallpaper with user-controlled dimming from 0% to 100%, warm white text, native app icons, quiet native sheets. Long-press management uses a deep navy surface and pale blue contour icons matching the supplied reference, an app icon/title header with tap-to-rename, inline additional actions without a rename row, and a separated settings entry. A native 300ms decelerating rise and 180ms downward exit preserve the sheet’s relationship to the bottom edge and honor disabled system animations.
STORY: Open an app directly, drag the alphabet to find another, hold an app icon for its pop-up or its name for management.
FIRST VIEWPORT: An unboxed vertical favorite list without a launcher clock or date; time stays in the Android status bar; a compact Latin alphabet at the lower right with # only when populated (16sp resting letters, 22dp letter step growing with font scale, and 24dp clearance above system navigation; short windows cap letter size to the available step); no bottom navigation buttons or reserved footer on normal home. Use real installed apps. The curved alphabet tracks every finger movement and highlights the selected section; navigation runs on section changes. The app list recycles visible native rows and jumps directly to the latest selected section. Cyrillic names share the first Latin letter of Android ICU Russian-Latin/BGN transliteration (Яндекс → Yandeks → Y); numbers and initials without Latin transliteration use the final #. Every window shows only populated A–Z and # sections from visible apps, plus ★ for returning to favorites.
FORM: User-pinned Niagara composition; no concept roll replaces an explicit reference. Native implementation, code-led because composition is specified.
FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Hidden apps and search

Hidden apps are excluded from the empty app list and alphabet. A nonblank search includes them using the same original-name/alias matching as visible apps. Long press on a hidden result exposes “Показывать снова” directly in the shared navy menu. The action removes hiding immediately while retaining the query/results; favorites stay as selected. Visible apps expose “Скрыть приложение” directly in the same flat action list.

## Favorites order

Home has no reorder button below favorites. “Изменить порядок” in a favorite app’s long-press menu enables ordering on home. Ordering retains the actual app/folder rows with one trailing 48dp handle on the same title line, centered with the name, including wrapped labels and notification previews below. There is no separate controls line or visible up/down button. Keyboard up/down and named accessibility moves live on the focused handle; boundaries omit the corresponding action. Favorites stay transparent over the wallpaper throughout dragging, including apps and folders; elevation keeps the moving row above its neighbors. Dropping saves, cancel preserves order, and edge scrolling supports long lists. Done remains in the fixed footer; Back ends the mode and HOME restores normal home. Unavailable IDs and existing selection/folder management remain intact.

## Widgets and navigation

The home screen hosts at most one widget. A rightward swipe on wallpaper, app/folder rows or other free space opens a separate widget page physically to its left; a leftward swipe on that page returns home. Catalog and notification updates defer rebuilding home until the current touch ends and any open sheet closes, keeping active holds and the scroll position. App rows no longer open pop-ups on swipe; hosted widgets and ordering handles keep their touch handling, and the outer 24dp system Back edge is excluded. App rows in the full list and search results also navigate to widgets on a rightward swipe; the search field retains editing gestures. The footer widget button provides a keyboard/accessibility alternative. The alphabet ends above the measured footer and respects system/IME insets, keeping every footer action reachable at large font sizes.

The widget page uses the wallpaper and occupies the complete inset-safe height, with no visible title, Back/Add/reorder toolbar, Home footer or extra vertical padding. Widgets retain 28dp side margins and the saved widget spacing. Holding empty wallpaper, a list gap or side margin opens the provider picker directly; the fill-viewport content keeps unused space touchable even on an empty or short page. The empty page only explains the hold gesture. A named accessibility long-click action and Menu/Shift+F10 on focused free space offer adding without a visible control. System Back and a leftward swipe return home. Ordering starts from the widget management menu for two or more widgets; Back ends ordering, and HOME returns normal home. Ordering stays on the same page with live hosted widgets and one trailing 48dp drag handle. The outer row stays transparent over the wallpaper while held and moved; elevation keeps it above neighbors, and the provider retains its own background. The handle supports drag, keyboard up/down and named accessibility moves with immediate saving; home binding, dimensions and offsets remain attached to each ID. Repeated provider names gain ordinal labels for the current editor session. Widgets form a vertically scrolling list with 28dp side margins and no alphabet overlay. Added widgets have no launcher titles or menu buttons above their content. Hold the widget to open resize, provider configuration when available, move and delete actions. The widget menu omits “О приложении” and “Добавить виджет” on both home and the widget page. Adding remains available by holding free space on the widget page and from the home-widget settings row; provider app details remain in the app long-press menu. The navy icon/title management sheet opens an editor over the live widget. Four 36dp arrow handles inside 48dp targets resize its upper/lower and left/right edges directly, with no circular reset buttons or slider dialog. The home widget starts immediately at the inset-safe top with no additional top reserve in any window and has its own full-width region, independent of the favorites/alphabet margins. Its default width is centered with approximately 36dp margins plus framework/provider padding. Side handles can expand it to the exact inset-safe window width, including widths between grid points, subject to provider max bounds. The alphabet remains above the expanded widget and keeps its Back corridor. Drag the body to move in both axes inside its region and the visible editing area; sizes and movement snap to a fine 12dp grid within provider constraints. Width resizes around its saved center, clamping horizontal offset when necessary; moving the upper edge preserves the lower edge. Sizes save immediately within provider-supported directions/bounds and the available window; Done, an outside tap, Back or HOME end editing. Keyboard arrows and four named accessibility actions move the focused body; range actions resize the same edges. The menu uses a four-direction arrow icon for moving/resizing and omits reset and transfer from home to the widget page; page widgets retain placement on home. Local dimensions and both position offsets survive recreation and portable backup import. Taps and scrolling reach provider content; movement, cancellation and detachment cancel pending holds. Keyboard Menu/Shift+F10 and a named accessibility long-click action open the same controls. Selecting another home widget moves the previous one to the widget page. Back and HOME return home; rotation retains the widget page and its scroll. Page transitions use a short directional slide/fade and honor disabled system animations.

Releasing an active gesture below the letters selects the final section even without a final MOVE. Each completed active gesture emits exactly one CLOCK_TICK on release, identical to section-change feedback, including release on the same section or below the letters. A final hash selection on release shares that tick. After cancellation, a late release does not restart navigation or emit haptic feedback. Android haptic settings remain respected.

Adding a widget opens a sheet with a fixed title/Close, a recycled list of widget labels, application names and 144dp provider previews, plus the shared alphabet control on the right. Provider preview layouts take precedence over images; missing previews are explicitly labeled. The star jumps to the start, Cyrillic labels share Latin sections, and # is last when populated. The list reserves 72dp for the rail; every sheet shows only populated provider sections, with letter size capped to fit short windows. Previews are inert, rows are accessible choices, and browsing allocates no widget IDs. Dismissal cancels resource loading; choosing a row continues the existing binding/configuration flow.

## Всплывающие сообщения

Все сообщения Better Launcher, включая «Приложение скрыто» с действием «Отменить», можно закрыть горизонтальным смахиванием в любую сторону. Они исчезают максимум через три секунды, в том числе при удержании пальца. Короткий или отменённый жест возвращает сообщение на место; закрытие не отменяет выполненное действие. Новое сообщение заменяет предыдущее. При открытом меню сообщение отображается поверх активного окна; перенос между окнами не продлевает срок. Escape/Delete при фокусе и accessibility-действие закрытия доступны без свайпа. Сообщения учитывают system/cutout/IME insets и растут при переносе текста.

## Shared widget spacing

The widget page and home information-to-favorites boundary use one saved `widgetSpacing` value: default 8dp, 0–32dp in 1dp steps. Appearance settings expose an inline Material slider with autosave, keyboard and accessibility input, plus a labeled schematic of two widgets and favorites whose two gaps update immediately. Its height reserves the maximum spacing, preventing list shifts; native labels grow with system fonts. The value stays identical in portrait, short windows and either rail mode. Widget ordering uses the same spacing around its existing handles. Framework host top/bottom padding is removed; its side padding stays in place. Provider-owned padding and explicit saved top offsets belong to the widget geometry, not this gap. Provider size options compensate for the framework API subtracting default padding, so reported height matches actual content.
